## 读之前：整条链路只有一句话

```
BGR 图 →[①检测]→ N 个 (框 + 5 点) →[②对齐]→ N 张 112×112 →[③特征]→ N 个 512 维向量
       →[④比对]→ 每人一个 (姓名, 相似度) →[⑤时序]→ 每条轨迹一个稳定身份
```

模块目录与阶段是**一一对应**的：

```
face_system/
├── config.py            ← 公共：全部超参集中在这里
├── utils.py             ← 公共：IO / 数学 / 绘图小工具
├── detectors/
│   ├── base.py          ← 公共：Face 数据结构（全链路的数据契约）
│   ├── yunet.py         ← ① 检测（主）
│   └── centerface.py    ← ① 检测（备选）
├── align/
│   ├── matlab_cp2tform.py  ← ② 解相似变换（纯数学）
│   ├── align_trans.py      ← ② 模板 + warp（复用的 evoLVe 源码）
```

## 二、公共层：三个模块决定了后面能不能解耦

### 2.1 `config.py` —— 所有魔法数字的唯一出处

**职责**：把路径、模型名、阈值、尺寸集中成 `CFG` 一个对象。所有脚本 `from face_system.config import CFG`，不硬编码。

**输入**：无（模块导入时构造）。
**输出**：`CFG.detector` / `CFG.align` / `CFG.rec` / `CFG.train` 四个 dataclass。

| 分组 | 关键字段 | 值 | 为什么是这个值 |
|---|---|---|---|
| `DetectorCfg` | `input_size` | `(640, 640)` | 三尺度特征图 80/40/20，够覆盖常见人脸尺度 |
| | `score_threshold` | `0.6` | 低了会把背景吃掉，高了漏侧脸 |
| | `max_side` | `1280` | 大图先降采样，1ms 换 3 倍速度 |
| | `min_face` | `24` | 小于 24px 的脸 ArcFace 也认不准，直接丢 |
| `AlignCfg` | `crop_size` | `112` | ArcFace 标准输入，不能改 |
| | `align_type` | `similarity` | 4 自由度，不拉伸五官 |
| | `auto_fix_reflection` | `True` | 侧脸左右眼判反时自动纠正 |
| `RecCfg` | `match_threshold` | `0.35` | w600k_r50 在 1e-3 FAR 处的量级 |
| | `ema_alpha` | `0.6` | 新帧 6 成、历史 4 成 |
| | `vote_window` | `15` | 半秒窗口，够压抖动又不迟钝 |
| `TrainCfg` | `depth` / `margin` / `scale` | `18` / `0.35` / `30` | 小样本从零训，18 层够用 |

另外两个函数解决 Windows 上的真实问题：

```python
def setup_cuda_env():
    """把 pip 安装的 CUDA 运行库 DLL 目录塞进 PATH（Windows + torch 常见坑）"""
    ...
    for sub in base.glob("*/bin"):
        os.add_dll_directory(str(sub))

def resolve_onnx_providers(prefer_gpu=False):
    """GPU 不可用自动回落 CPU，避免 InferenceSession 直接抛异常"""

```

### 2.2 `utils.py` —— 无状态工具箱

**职责**：分四类，都不持有状态。

| 类别 | 函数 | 输入 → 输出 | 用在哪 |
|---|---|---|---|
| 中文路径 IO | `imread` / `imwrite` | 路径 → `ndarray` / 反之 | 全工程 |
| 数学 | `l2norm` / `cosine_sim` | 向量 → 向量 / 矩阵 | gallery、tracker |
| 几何 | `bbox_iou` / `center_dist` | 两个 `xywh` → `float` | tracker 关联 |
| 绘图 | `draw_face_box` / `put_text_scale` | 图 + 框 + 文字 → 图 | step2/4/5、app |

**关键代码 1：中文路径 IO。** `cv2.imread` 在 Windows 上遇到中文路径会静默返回 `None`，所以绕一层：

```python
def imread(path):
    buf = np.fromfile(str(path), dtype=np.uint8)      # 用 numpy 读字节，绕开 OpenCV 的窄字符路径
    return cv2.imdecode(buf, cv2.IMREAD_COLOR) if buf.size else None

def imwrite(path, img):
    ok, buf = cv2.imencode(Path(path).suffix, img)     # 先编码成内存字节
    buf.tofile(str(path))                              # 再用 numpy 落盘
    return ok
```

**关键代码 2：文字贴片缓存。** `cv2.putText` 不支持中文，用 PIL 渲染；但**每帧整图转一次 PIL 会直接把 16 FPS 拖到 5 FPS**，所以渲染结果按 `(文字, 字号, 颜色)` 缓存成小贴片，再按 alpha 混进 ROI：

```python
key = (text, size, tuple(color), alpha)
hit = _TEXT_PATCH_CACHE.get(key)          # 命中就直接返回，绝大多数帧都能命中
if hit is not None:
    return hit
...
img[y0:y1, x0:x1] = (roi * (1 - pa) + patch * pa).astype(np.uint8)   # 只混这个小矩形
```

### 2.3 `detectors/base.py` —— 全链路的数据契约

**职责**：定义 `Face` 和 `BaseDetector`。**这是整个工程最重要的 30 行**——因为对齐器和追踪器只认识 `Face`，所以换检测器（YuNet ↔ CenterFace）不用改下游任何代码。

**输入**：无。
**输出**：`Face` 类 + 抽象方法 `detect()`。

```python
@dataclass
class Face:
    bbox: np.ndarray            # [x, y, w, h]，原图像素坐标，不是归一化
    score: float = 1.0
    landmarks: np.ndarray | None = None   # (5,2)，顺序：[左眼, 右眼, 鼻尖, 左嘴角, 右嘴角]
```

三个细节值得注意：

1. **`bbox` 用 `xywh` 而不是 `xyxy`**。因为 `cv2.rectangle`、`warpAffine` 的 ROI、`bbox_iou` 全都用 `xywh` 更顺；`xyxy` 只在画框瞬间临时算。
2. **`landmarks` 的顺序是硬约定**，且必须是「图像坐标下的左右」，与 ArcFace 模板一致。这是后面镜像自纠正要兜的底——不同检测器对「主体左眼 / 图像左眼」的理解不一样。
3. **`crop(pad)` 和 `clipped(W,H)` 是给特殊场景准备的**：前者按框外扩裁剪（可视化用），后者把越界的框夹回图内（边缘人脸用）。

`BaseDetector` 只有一个必须实现的方法：

```python
class BaseDetector:
    def detect(self, img, **kwargs) -> List[Face]:
        raise NotImplementedError
    def detect_one(self, img):            # 单人场景取最高分
        faces = self.detect(img)
        return max(faces, key=lambda f: f.score) if faces else None
```

### 2.4 `__init__.py` —— 一行拿到三个模型

**职责**：工厂函数，把「配置 → 实例」这段样板代码收起来。

**输入**：检测器名字（`'yunet'` / `'centerface'`）。
**输出**：`(detector, aligner, rec)` 三元组。

```python
def build_pipeline(detector=None, prefer_gpu=False, crop_size=None):
    det = build_detector(detector, prefer_gpu=prefer_gpu)
    aligner = FaceAligner(det, crop_size=crop_size or CFG.align.crop_size, ...)
    rec = ArcFaceONNX(CFG.rec.model, prefer_gpu=prefer_gpu)
    return det, aligner, rec
```

**为什么要这个函数**：脚本里写一行就能跑起来，而且三者的参数（`crop_size=112`）天然对齐——`aligner` 输出 112，`rec` 也吃 112，不会出现「对齐成 96 但模型要 112」的静默错误。

## 三、① 检测：`detectors/yunet.py`（207 行）

**职责**：找出图里所有人脸，给出框 + 置信度 + 5 个关键点。

| 项目 | 内容 |
|---|---|
| **输入** | `img`：BGR `H×W×3`，任意尺寸 |
| **输出** | `List[Face]`，按 `score` 降序，坐标已还原到**原图**尺度 |
| **阶段** | ① 检测（链路第一环） |
| **被谁调用** | `FaceAligner.run()`、`step1/2/4/5/6`、`app` |

内部流程五步：

```
原图 → ① max_side 降采样 → ② letterbox 到 640×640 → ③ 网络前向（3 个 stride）
     → ④ 解码 + NMS → ⑤ 坐标乘 1/scale 还原 + min_face 过滤
```

**关键代码 1：降采样与还原。** 大图先缩小，检测完再把坐标乘回去——这是「速度线性提升、精度几乎无损」的来源：

```python
if limit and max(W, H) > limit:                  # limit = max_side = 1280
    scale = limit / float(max(W, H))
    work = cv2.resize(img, (int(W * scale), int(H * scale)))
faces = self._detect_ort(work)                   # 在小图上检测
inv = 1.0 / scale
f.bbox = f.bbox * inv                            # 坐标还原回原图
f.landmarks = f.landmarks * inv
```

**关键代码 2：anchor-free 解码。** 网络输出的是「相对格子的偏移」，必须解回像素坐标，这是整个检测头唯一的难点：

```python
score = np.sqrt(np.clip(cls, 0, 1) * np.clip(obj, 0, 1))   # 分类分 × 目标性分，再开方
cx = (cc + b[:, 0]) * st        # cc 是格子列号，b[:,0] 是回归的偏移，乘 stride 回像素
cy = (rr + b[:, 1]) * st
bw = np.exp(np.clip(b[:, 2], -6, 6)) * st    # 宽回归的是 log(w)，exp 回来保证为正
bh = np.exp(np.clip(b[:, 3], -6, 6)) * st
k[:, :, 0] = (cc[:, None] + k[:, :, 0]) * st # 5 个关键点同样要「加格子 + 乘 stride」
```

> `clip(-6, 6)` 是为了防止 exp 溢出成 inf（训练崩过的人会懂）。

**关键代码 3：双后端。** OpenCV 5.0 的新 ONNX 解析器读不了这个模型（报 `Can't read ONNX file`），所以留了 `onnxruntime` 手写解码兜底：

```python
if backend in ("auto", "cv2"):
    try:
        self._det = cv2.FaceDetectorYN.create(...)
        self.backend = "cv2"
    except Exception:
        print("[YuNet] cv2 后端不可用，回退到 onnxruntime")
if self.backend is None:
    self._sess = ort.InferenceSession(...)
    self.backend = "ort"
```

**这个模块的坑**：`input_size` 传的是 `(w, h)` 不是 `(h, w)`；而 ONNX 拿到的可能是 `(1,3,H,W)`，所以初始化时会反向读一次 shape 覆盖，否则 letterbox 会把图转置。

### `detectors/centerface.py`（116 行，备选）

**职责**：同一接口的第二个实现，验证「检测器可插拔」。

| 项目 | 内容 |
|---|---|
| **输入** | `H×W×3` |
| **输出** | `List[Face]`（同样带 5 点） |
| **与 YuNet 的差别** | CenterNet 风格：先出**热图**（人脸中心点的概率图），再回归宽高/偏移/关键点 |

**关键代码**：热图分辨率是输入的 1/4，所以坐标要乘 4：

```python
heatmap = outs[0][0, 0]                     # (H/4, W/4)，每个像素是"人脸中心"的置信度
ys, xs = np.where(heatmap > self.score_threshold)
# 关键：heatmap 是 1/4 分辨率，坐标要乘 4 再加中心偏移
cx = (xs + ox) * 4.0
cy = (ys + oy) * 4.0
lm[:, :, 0] = lm[:, :, 0] * 4.0 + (xs[:, None] * 4.0)   # 关键点同样是"相对格点 + 乘 4"
```

**它的价值**：只要继承 `BaseDetector` 实现 `detect()`，`--detector centerface` 就能直接跑通全链路——这就是 `base.py` 那个契约的收益。

## 四、② 对齐：三个模块分工明确

### 4.1 `align/matlab_cp2tform.py`（135 行）—— 纯数学，不碰图

**职责**：给两组 5 个点，解出 `2×3` 相似变换矩阵。

| 项目 | 内容 |
|---|---|
| **输入** | `src_pts (5,2)`：检测到的关键点；`dst_pts (5,2)`：112×112 模板点 |
| **输出** | `2×3` 矩阵，可直接喂 `cv2.warpAffine` |
| **阶段** | ② 对齐的第一步（解方程） |

**数学**：相似变换只有 4 个自由度，写成

```
x' = sc·x − ss·y + tx
y' = ss·x + sc·y + ty
```

`sc, ss, tx, ty` 是 4 个未知数；每个点给 2 个方程，5 个点给 10 个方程 → **超定方程组** → 最小二乘。

**关键代码**：把方程堆成矩阵，一次 `lstsq` 解掉（比 SVD/Umeyama 更直白）：

```python
tmp1 = np.hstack((x, y, np.ones((M,1)), np.zeros((M,1))))   # 每个点的第 1 个方程系数
tmp2 = np.hstack((y, -x, np.zeros((M,1)), np.ones((M,1))))  # 第 2 个方程系数
X = np.vstack((tmp1, tmp2))          # (2M, 4)
U = np.vstack((u, v))                # (2M, 1)
r, *_ = lstsq(X, U, rcond=None)      # 解出 [sc, ss, tx, ty]
```

还有一个 `findSimilarity()`：如果解出来的残差很大，会**先沿 Y 轴镜像目标点再解一次**，取残差小的那个——这是原版就有的容错，用来对付「关键点顺序可疑」的情况。

### 4.2 `align/align_trans.py`（188 行）—— 模板 + warp（复用 evoLVe）

**职责**：提供 5 点参考模板，并按矩阵把脸 warp 到 112×112。

| 项目 | 内容 |
|---|---|
| **输入** | `src_img`、`facial_pts (5,2)`、`crop_size`、`align_type` |
| **输出** | `112×112×3` 的 BGR 人脸 |
| **阶段** | ② 对齐的第二步（执行变换） |

**关键代码 1：112×112 模板怎么来的。** 原版模板是 96×112 的，正方形输出时把宽度补齐：

```python
if default_square:
    size_diff = max(tmp_crop_size) - tmp_crop_size     # [16, 0]
    tmp_5pts += size_diff / 2                          # 整体右移 8 像素
```

得到 `[[38.29,51.70],[73.53,51.50],[56.03,71.74],[41.55,92.37],[70.73,92.20]]`——这就是 ArcFace 的标准 112 模板。

**关键代码 2：三种对齐方式的分支。**

```python
if align_type == 'cv2_affine':
    tfm = cv2.getAffineTransform(src_pts[0:3], ref_pts[0:3])   # 只用 3 点，6 自由度
elif align_type == 'affine':
    tfm = get_affine_transform_matrix(src_pts, ref_pts)        # 用 5 点，6 自由度
elif align_type in ('similarity', 'smilarity'):                # ← 本实验用这个，4 自由度
    tfm = get_similarity_transform_for_cv2(src_pts, ref_pts)

return cv2.warpAffine(src_img, tfm, (crop_size[0], crop_size[1]),
                      flags=cv2.INTER_LINEAR, borderMode=cv2.BORDER_REPLICATE)
```

**改了什么（对应「修改源码」要求）**：

| 改动 | 原版问题 | 现在 |
|---|---|---|
| 删掉 MTCNN 依赖 | `face_align.py` 内部调 `detect_faces()` | 5 点从外部传入，与检测器解耦 |
| 正方形输出不再抛异常 | `crop_size=(112,112)` 且 `reference_pts=None` 时报 `FaceWarpException` | 自动走 `default_square=True` |
| `is` → `==` | `if align_type is 'cv2_affine'` 在 3.8+ 是语法告警 | 改成 `==` |
| 保留 `'smilarity'` 别名 | 原版拼错少一个 i，拼错会**静默**走 similarity 分支 | 保留别名 + 加显式校验，拼错直接报错 |

`borderMode=cv2.BORDER_REPLICATE` 这个参数有讲究：变换后人脸边缘会超出原图，用「复制边缘像素」而不是补黑，避免对齐图出现黑边污染特征。

### 4.3 `align/align_pipeline.py`（191 行）—— 本实验的核心改造

**职责**：把检测器的 `Face` 喂给 evoLVe 的 warp，并在中间塞一道**镜像自纠正**。

| 项目 | 内容 |
|---|---|
| **输入** | `img` + `Face`（或整张图，走 `run()` 自己检测） |
| **输出** | `AlignedFace`（`crop` 是 112×112，另带 `tfm`、`swapped`、`eye_dy` 便于调试） |
| **阶段** | ② 对齐的总入口 |
| **被谁调用** | 所有脚本（`aligner.run(img)` 或 `aligner.align_face(img, face)`） |

**关键代码 1：镜像自纠正。** 有的检测器把「主体右眼」放在第 0 位，有的放「图像左眼」。判反了会解出带反射的矩阵，脸被镜像贴到模板上——**这种情况不会报错，只会让相似度悄悄掉下来**。所以用行列式符号检测：

```python
tfm = get_similarity_transform_for_cv2(pts5, self.ref_pts)
det = float(np.linalg.det(tfm[:, :2]))          # <0 → 含反射，说明左右点被搞反了

if det < 0 and self.auto_fix_reflection:
    pts2 = pts5[_MIRROR_SWAP]                    # _MIRROR_SWAP = [1,0,2,4,3]
    tfm2 = get_similarity_transform_for_cv2(pts2, self.ref_pts)
    det2 = float(np.linalg.det(tfm2[:, :2]))
    if det2 > 0:                                 # 重解后不反射了才采纳
        return tfm2, True, det2
return tfm, False, det
```

行列式为什么能判反射：相似变换矩阵的 2×2 子块是 `s·R`，`det(sR) = s²·det(R)`；纯旋转 `det(R)=+1`，一旦含镜像 `det=−1`。

**关键代码 2：自检指标 `eye_dy`。** 对齐是否成功，用「两眼是否水平」来验证——理想值 0：

```python
pts = np.hstack([face.landmarks, np.ones((5, 1))]) @ np.vstack([tfm, [0, 0, 1]]).T
eye_dy = float(abs(pts[0, 1] - pts[1, 1]))       # 实测均值 0.30 px，最大 0.74 px
```

**关键代码 3：批量对齐 `align_folder()`。** 替代原版 `face_align.py` 的循环，给数据集用：

```python
face = max(faces, key=lambda f: f.area)          # 数据集场景取最大人脸，忽略背景路人
af = aligner.align_face(img, face)
stats["swapped"] += int(af.swapped)              # 统计触发镜像纠正的次数
imwrite(out_sub / (p.stem + ".jpg"), af.crop)
```

## 五、③ 特征：两个模块，一个推理一个训练

### 5.1 `backbone/arcface_onnx.py`（85 行）—— 推理

**职责**：把人脸图变成 512 维特征向量。

| 项目 | 内容 |
|---|---|
| **输入** | `List[112×112×3]`（BGR） |
| **输出** | `(N, 512)` ndarray，**已 L2 归一化** |
| **阶段** | ③ 特征 |
| **模型** | `w600k_r50.onnx`（ArcFace + ResNet50，Glint360K 36 万人训练） |

**关键代码 1：预处理必须和训练一致。** 这两个常数错了，相似度会整体偏移但不会报错：

```python
rgb = cv2.cvtColor(im, cv2.COLOR_BGR2RGB).astype(np.float32)   # BGR → RGB
rgb = (rgb - 127.5) / 127.5                                    # 归一到 [-1, 1]
batch[i] = rgb.transpose(2, 0, 1)                              # HWC → CHW
```

**关键代码 2：分块推理绕开写死的 batch。** 模型输出 shape 写死成 `{1,512}`，一次喂 15 张会报 `Expected shape {1,512} does not match {15,512}`：

```python
for i in range(0, len(faces), batch_size):          # batch_size=8
    chunk = faces[i:i + batch_size]
    out = self.sess.run(self.output_names, {self.input_name: self._preprocess(chunk)})[0]
    feats.append(np.asarray(out, np.float32).reshape(len(chunk), -1))
return l2norm(np.vstack(feats))                     # 出口统一归一化
```

**归一化放在出口而不是调用处**：这样「内积 = 余弦」这个约定只在一个地方保证，`gallery` 和 `tracker` 就不用各自再归一化一次。

### 5.2 `backbone/iresnet.py`（170 行）—— 训练用骨干

**职责**：训练实验（step7）里从零训的 iResNet，结构对齐 insightface，方便和预训练模型对比。

| 项目 | 内容 |
|---|---|
| **输入** | `(N, 3, 112, 112)` tensor |
| **输出** | `(N, 512)` **未归一化**特征（归一化交给 `MarginHead` 里的 `F.normalize`） |
| **阶段** | ③ 特征（离线训练，不参与部署推理） |

**关键代码：茎层必须有 stride=2。** 这里少写一个 stride 就是当时训练崩的原因：

```python
self.input_layer = nn.Sequential(
    BNConv(3, 64, (3, 3), (1, 1), 1),      # 112 → 112
    BNConv(64, 64, (3, 3), (2, 2), 1),     # 112 → 56  ← 关键，漏了就变 14×14
)
...
nn.Linear(512 * (input_size // 16) * (input_size // 16), emb_dim)   # 512×7×7 = 25088
```

`112/16 = 7`：茎层降一次（56），4 个 stage 里 3 个再降一次（28→14→7）。漏了茎层那个 stride，特征图停在 14×14，展平后是 100352，和全连接层的 `in_features` 对不上，报 `mat1 and mat2 shapes cannot be multiplied`。

参数：`units=(2,2,2,2)` → 24.06 M；`(3,4,6,3)` → 43.84 M；`(3,13,30,3)` → 65.55 M。

## 六、④ 比对：`gallery.py`（208 行）

**职责**：注册身份、存特征、1:1 验证、1:N 检索。

| 项目 | 内容 |
|---|---|
| **注册输入** | `name` + `List[512 维特征]` |
| **查询输入** | 1 个 `512` 维特征 |
| **输出** | `(姓名或"未知", 相似度, top-k 列表)` |
| **阶段** | ④ 比对 |
| **持久化** | `npz`：`names` / `id_feats` / `face_feats` / `meta` / `threshold` |

**关键设计 1：一个身份存两种特征。** 注册 15 张图时，同时保留「均值特征」和「逐脸特征」：

```python
mean = l2norm(F.mean(0))[None, :]        # 单位球上的质心，检索用这个
self.id_feats = np.vstack([self.id_feats, mean])
self.face_feats.append(F)                # 逐脸特征，给 face_level 策略用
```

**为什么**：均值特征抗噪，是默认检索方式；逐脸特征支持「取 top-3 均分」，对多姿态注册更鲁棒（可选开关 `face_level=True`）。

**关键设计 2：检索就是一次矩阵乘。**

```python
def search(self, feat, topk=5):
    sims = cosine_sim(feat, self.id_feats)[0]      # (1,512)·(512,M) → (M,)，每个数就是余弦
    order = np.argsort(-sims)[:topk]               # 降序取 topk
    return [(self.names[i], float(sims[i])) for i in order]
```

**关键设计 3：阈值拒识就是开放集。**

```python
def identify(self, feat, threshold=None, topk=5):
    name, sim = self.search(feat, topk)[0]
    return (name if sim >= thr else "未知"), sim, res
```

`argmax` 只能回答「最像谁」，`≥τ` 才能回答「是不是库里的人」。少了这一步，任何陌生人都会被强行认成库里最像的那个——这是人脸识别系统最典型的错误设计。

**辅助方法**：`register_from_raw_dir()` 直接吃原始照片（内部自动检测→对齐→提特征），`verify_images()` 直接比两张原图。

## 七、⑤ 时序：`tracker.py`（176 行）

**职责**：让同一个人在多帧里保持同一个身份，不闪烁。

| 项目 | 内容 |
|---|---|
| **输入** | 本帧 `faces: List[Face]`、`feats: (N,512) 或 None`、底库 |
| **输出** | `List[Track]`，每个 `Track` 带 `tid / bbox / name / sim / hits` |
| **阶段** | ⑤ 时序 |
| **被谁调用** | `step5_video_demo.py`、`app/attendance_demo.py` |

**`Track` 的关键字段**：

| 字段 | 含义 | 为什么需要 |
|---|---|---|
| `feat` | EMA 融合后的特征 | 比单帧特征稳 |
| `vel` | 速度（中心的帧间位移） | 快速运动时 IoU 失效，靠它预测位置 |
| `lost` | 连续丢失帧数 | 超过 `max_lost` 才删轨迹，容忍遮挡 |
| `votes` | 最近 15 次 `(身份, 相似度)` | 多数票 |
| `feat_fresh` | 本帧是否更新了特征 | 关键帧策略的开关 |
| `trail` | 中心点轨迹（最长 40） | 画运动轨迹 |

**关键代码 1：EMA 特征融合。** 一行公式解决「遮挡/侧脸污染特征」：

```python
if feat is not None:
    f = np.asarray(feat, np.float32).ravel()
    if self.feat is None:
        self.feat = l2norm(f)                                    # 首帧直接作为初值
    else:
        self.feat = l2norm(alpha * l2norm(f) + (1 - alpha) * self.feat)   # f_t = norm(α·f_new + (1-α)·f_{t-1})
    self.feats_seen += 1
    self.feat_fresh = True
```

融合后必须**重新归一化**，否则模长会漂移，余弦相似度就不准了。α=0.6 意味着历史权重每帧衰减到 0.4，约 3 帧后旧信息只剩 6 %。

**关键代码 2：多数票 + 相似度中位数。**

```python
recent = list(self.votes)[-vote_window:]            # 最近 15 帧
top_name, top_cnt = Counter([n for n, _ in recent]).most_common(1)[0]
if top_cnt < max(2, len(recent) // 2):               # 票数不过半 → 维持原判或"识别中"
    ...
sims = np.array([s for n, s in recent if n == top_name])
self.name, self.sim = top_name, float(np.median(sims))   # 用中位数，不用均值（抗离群）
```

**关键代码 3：`TrackManager.step()` 的五步。** 这是整个视频链路的骨架：

```
1) 关联：算 (轨迹 × 检测) 的 IoU，贪心配对（IoU≥0.3 或 归一化中心距<0.5）
2) 新建：没配上的检测框 → 开新轨迹，tid += 1
3) 计丢：没配上的轨迹 → lost += 1，并用 vel 外推位置
4) 识别：feat 非空 且 本帧没丢 且 本帧有新特征 → identify() → 投票 → decide()
5) 清理：lost > max_lost 的轨迹删掉
```

**为什么用 IoU + 中心距两条规则**：只靠 IoU，快速移动（相邻帧框不重叠）会断轨；只靠中心距，人脸密集时会串号。所以先试 IoU，不达标再用「中心距 / 框宽 < 0.5」兜底。

**这个模块的坑**：`decide()` 里要求票数 `≥ max(2, W/2)`，如果投票窗口设成 1，条件永远不成立，界面上就一直显示「识别中」。所以加了特判：

```python
if len(recent) == 1:                        # 窗口=1 时直接用当前帧结果
    self.name, self.sim = recent[0][0], recent[0][1]
```

## 八、训练侧：三个模块解释「为什么 margin 有用」

这一组**不在推理链路里**，跑完就出三个模型和三张图，用来支撑报告里的「训练原理」一节。

### 8.1 `train/dataset.py`（103 行）

| 项目 | 内容 |
|---|---|
| **输入** | 目录 `data/lfw20_aligned/train/<身份>/*.jpg`（已对齐的 112×112） |
| **输出** | `(tensor 3×112×112, label int)` |
| **增强** | 水平翻转 p=0.5、仿射（±10°、0.9~1.1 倍、±5 % 平移）、亮度/对比度/饱和度扰动、随机擦除 |

增强里有个取舍值得写进报告：**水平翻转对人脸识别是有争议的**（会改变左右脸语义），这里按 p=0.5 用，但验证集严格不翻转，保证线上线下一致。

### 8.2 `train/losses.py`（87 行）—— 三种 loss 只差一行

| 项目 | 内容 |
|---|---|
| **输入** | `feat (N,512)`、`label (N,)` |
| **输出** | `(N, num_classes)` 的 logits |
| **关键** | 先把特征和权重都归一化，`logits = s·cosθ` |

```python
cos = F.linear(F.normalize(feat), F.normalize(self.weight)).clamp(-1+1e-7, 1-1e-7)

if self.mode == "softmax" or self.m == 0:
    return cos * self.s                                   # 基线
# cosface: 目标类 cos 减去 m
# arcface: cos(θ+m) = cosθ·cos m − sinθ·sin m
```

`clamp` 不是可有可无：`arccos(1.0)` 的导数是无穷大，NaN 就是从这里来的。

### 8.3 `train/train_margin_compare.py`（256 行）+ `analyze_geometry.py`（197 行）

| 脚本 | 做什么 | 产出 |
|---|---|---|
| `train_margin_compare.py` | 同一数据/增强/骨干，只换 loss，各训 40 epoch | 三份权重 + `*_metrics.json` + 曲线图 |
| `analyze_geometry.py` | 重载三份权重，算 `intra` / `inter_max` / `proto_gap`、画 PCA | `geometry_compare.json`、`pca_compare.png` |

**为什么要 `analyze_geometry.py` 单独一个脚本**：训练脚本只能告诉你「准确率多少」，但人脸识别的关键是「特征空间长什么样」。而且一开始用的「平均类间相似度」是坏指标——归一化后随机方向的期望就是 0，三种 loss 都≈0，完全看不出差别；换成 `inter_max`（每个类最像的那个负类）才有区分力。

## 十三、顶层目录：八个文件夹各是什么

前面十二节讲的是「文件里写了什么」，这一节讲「为什么这样摆」。八个目录的分工可以一句话概括：

```
models/  权重      ┐
data/    数据      ├─→ face_system/ 库（只有函数，没有 main）─┐
                   │                                          ├─→ scripts/ 实验步骤（有 main，落盘到 outputs/）
                   │                                          └─→ app/      应用（把库拼成一条业务）
                   └─→ train/ 训练侧（与部署解耦，产物不进推理链路）

outputs/ 产物 ─→ tools/ 出图与出文档 ─→ 实验报告.docx / 实验七_教学讲义.html
```

判据只有一条：**目录里有没有 `if __name__ == "__main__"`**。
有 → 它是「可执行的一步」，必然往 `outputs/` 里写东西；没有 → 它是「被调用的库」，改了要保证所有调用方都不崩。

### 13.2 `face_system/`：库，不产生任何文件

**这是唯一"没有副作用"的目录**——所有函数都只吃参数、吐返回值，不读配置常量以外的全局状态，不 `print`（除少数 `logging`），不写盘。

正因如此，`app/attendance_demo.py` 才能只用 20 行就把五段串起来：它不需要知道模型在哪、参数多少、图片怎么解码。

```python
from face_system import build_pipeline          # 一次建好检测+对齐+特征
det, aligner, rec = build_pipeline()
faces  = det.detect(frame)                      # ①
crop   = aligner.align_face(frame, faces[0]).crop  # ②
feat   = rec.get_feat([crop])[0]                # ③
name, sim = gallery.identify(feat, thr=0.35)    # ④
tracks = tm.step(faces, feats, gallery)         # ⑤
```

**唯一允许写盘的是两个 `*_folder` 辅助函数**：`aligner.align_folder()` 与 `Gallery.save()`，它们是给 `scripts/` 用的便利封装，不是推理必经之路。

目录内部按阶段再分四层，是为了让「换检测器」只动一个文件：

```
detectors/  ← 换检测器只需新增一个文件 + 在 __init__ 注册
align/      ← 换对齐算法只需改 align_pipeline，模板与变换保持不动
backbone/   ← 换特征模型只需改 arcface_onnx（输入必须是 112×112）
gallery.py / tracker.py  ← 与"模型"无关，纯向量运算与状态机
```

最后一行是关键结论：**后两个模块（gallery / tracker）跟用什么模型毫无关系**。它们只认 `(M,512)` 和 `(512,)` 的数组，所以哪怕把 ArcFace 换成 FaceNet（128 维），只要改 `gallery` 的维度假设，比对与追踪的代码一行不用改。

### 13.3 `scripts/`：七步，一步一个可验收的产物

编号不是排版需要，而是**依赖顺序**——后一步读前一步的产物，跳步会报错。

| 脚本 | 行数 | 读什么 | 写什么 | 为什么单独一步 |
|---|---|---|---|---|
| `step0_download_models.py` | 133 | 网络 | `models/*.onnx` | 权重 167 MB，必须与代码分离；带 sha256 校验防下坏 |
| `step1_env_check.py` | 140 | `models/` + `data/` | 仅终端输出 | 冒烟测试：一次跑通 `(112,112,3)→(1,512)`，把环境问题挡在最前面 |
| `step2_detect_align.py` | 166 | `data/images/` `data/lfw20/` | `outputs/step2/` + `data/lfw20_aligned/` | 检测与对齐是**唯一需要人眼看**的环节，必须先出图确认 |
| `step3_build_gallery.py` | 138 | `data/*_aligned/` | `outputs/gallery/*.npz` | 底库是"数据"，不是"配置"；`npz` 可版本化、可复现 |
| `step4_static_test.py` | 336 | 底库 + 对齐图 | `results_static.json` + 4 张图 | 静态指标（1:1、1:N、FAR）与视频无关，先单独压实 |
| `step5_video_demo.py` | 427 | 视频 + 底库 | 3 个 mp4 + 3 个 json | 动态识别唯一一步；三种模式靠 `--mode` 切换，逻辑共用 |
| `step6_evaluate.py` | 476 | 全部产物 | `eval_results.json` + 4 张图 | 把前面散落的数字**收拢成一次统一评估**，含消融 |

设计上有一条隐含约定：**每个脚本只写自己的 `outputs/stepN/`，不碰别人的目录**。所以重跑 `step4` 不会污染 `step5` 的结果，报告里的图永远能对应到唯一来源。

`step6` 是唯一"读别人产物"的脚本（它读底库、读对齐目录），这也解释了为什么它 476 行最长——它要负责把不同来源的样本对齐成可比的形式（例如对齐目录已是 112×112，不能再检测一遍，否则会漏检）。

### 13.4 `train/`：训练侧，故意与部署断开

这是整个工程最容易误解的地方：**这里训出来的 `*_backbone.pth` 不参与任何推理**。

| 文件 | 行数 | 作用 |
|---|---|---|
| `dataset.py` | 103 | 读 `data/lfw20_aligned/`，做翻转/仿射/光度/随机擦除增强 |
| `losses.py` | 87 | `MarginHead`：softmax / cosface / arcface 三种 logits |
| `train_margin_compare.py` | 256 | 同一骨干、同一数据，只换损失，跑三遍对照 |
| `analyze_geometry.py` | 197 | 从三个 `.pth` 里提特征，算 `inter_max` / `proto_gap`，画 PCA |

训练侧的产物是**三个 `_metrics.json` 和几张图**，用途是回答「margin 到底有没有用」这个问题。推理用的是 `models/w600k_r50.onnx`（在百万级身份上预训练好的），因为 62 个身份、930 张图根本训不出可用的识别器。

所以两者的关系是：**`train/` 提供证据，`models/` 提供能力**。把 `train/` 整个删掉，`step0~6` 一切照常。

### 13.5 `models/`：只有两个文件，但一个是 167 MB

| 文件 | 大小 | 用途 | 谁加载 |
|---|---|---|---|
| `face_detection_yunet_2023mar.onnx` | 228 KB | ① 检测 | `detectors/yunet.py`（cv2 或 ort 后端） |
| `w600k_r50.onnx` | 167 MB | ③ 特征（ResNet-50 + ArcFace，WebFace600K 训练） | `backbone/arcface_onnx.py` |

路径不硬编码在任何模块里，全部走 `config.MODEL_DIR`：

```python
CFG.det.model_path   # → models/face_detection_yunet_2023mar.onnx
CFG.rec.model_path   # → models/w600k_r50.onnx
```

这样做的实际好处：换权重只改 `config.py` 一行，不动业务代码；`step0` 下载时也只需改配置就能指向镜像源。

**注意一个缺口**：`detectors/centerface.py`（116 行）写好了，但 `models/` 里**没有** `centerface.onnx`。所以 `--detector centerface` 现在会因缺权重而失败，要跑需自己补一个 1.8 MB 的 `centerface.onnx` 放进来。课程允许二选一，主链路用 YuNet 已满足要求。

### 13.6 `data/`：原始与派生混放，靠后缀区分

| 路径 | 内容 | 性质 |
|---|---|---|
| `data/images/self/` | 本人 15 张自拍 | **原始**，自采 |
| `data/lfw20/train/` | 62 身份 × 15 张 = 930 张 | **原始**，公开数据集 |
| `data/lfw20/valid/` | 62 身份 × 5 张 = 310 张 | **原始** |
| `data/lfw20_aligned/train/` | 930 张 112×112 | **派生**，`step2` 生成 |
| `data/lfw20_aligned/valid/` | 310 张 112×112 | **派生**，`step2` 生成 |

派生目录故意放在 `data/` 而不是 `outputs/`，原因是**它会被 `train/` 和 `step3` 当输入读**——放 `outputs/` 会让人误以为它是一次性产物。

代价是：重跑 `step2` 会覆盖 `lfw20_aligned/`，若此时正在训练会读到写了一半的文件。真要并行，得先复制一份改 `config` 路径。

`step2` 还会写两个 `align_fail_*.txt`，本次均为空文件——**空文件本身就是结论**（1240 张零失败），删掉反而丢了证据。

### 13.7 `outputs/`：一个脚本一个目录，编号即契约

| 子目录 | 内容 | 谁写的 |
|---|---|---|
| `step2/` | `detection_grid.jpg`、`alignment_grid.jpg`、`stats.json`、两个失败清单 | `step2` |
| `gallery/` | `gallery_lfw62.npz`（62 身份/930 特征）、`gallery_demo.npz`（13 身份/188 特征）、`self_split.json`（8/7 划分） | `step3` |
| `step4/` | `1to1_hist.png`、`1toN_top3.jpg`、`1toN_heatmap.png`、`1to1_probes.jpg`、`results_static.json` | `step4` |
| `step5/` | 3 个 `annotated_*.mp4`、`test_video.mp4`、3 张关键帧图、3 个 `video_stats_*.json` | `step5` |
| `step6/` | `eval_results.json`、`eval_summary.png`、`ablation_align*.{png,jpg}`、`quality_curve.png` | `step6` |
| `step7/` | 3 个 `*.pth`、3 个 `*_metrics.json`、`compare_curves.png`、`geometry_bars.png`、4 张 PCA 图 | `train/` |
| `figures/` | `pipeline.png`（流程图） | `tools/make_figures.py` |
| `app/` | `attendance_*.csv`、`attendance_demo.mp4` | `app/` |

三条约定值得记：

1. **`.json` 存数字，`.jpg/.png` 存观感**。报告里所有数值都从 json 取，不从图上读数——图只是给人看的。
2. **文件名带模式名**（`video_stats_track_fusion.json`、`annotated_track_nofusion.mp4`），三种模式的产物并列存放，对照时不用翻目录。
3. `outputs/app/_bench.mp4` 是当时测帧率的临时文件，**可以删**；`outputs/_preview/实验报告.pdf` 是 docx 导出的对照件，也可以删。

### 13.8 `tools/` 与 `app/`：面向人的两头

`tools/` 是**出口**——把 `outputs/` 里的散件变成一份能交的报告：

| 文件 | 行数 | 作用 |
|---|---|---|
| `build_report_docx.py` | 455 | Markdown → docx：轻量 LaTeX→Unicode、图片限高 18.5 cm、中文续行合并 |
| `make_figures.py` | 110 | 用 matplotlib 画 `pipeline.png`（不依赖 draw.io） |
| `build_deck.py` | 58 | 把 `deck_src.html` 里的 `<img src="../outputs/...">` 内联成 base64，产出单文件讲义 |
| `deck_src.html` | — | 46 页讲义的源文件（改这个，再跑 `build_deck.py`） |

`app/` 是**入口**——唯一"给使用者看"的目录。223 行里真正属于算法的只有 20 行，其余全是业务：轨迹首次确认才写 CSV、同一轨迹只记一次、无人脸帧跳过、输出带时间戳与相似度。它证明了这套库能落地，但它**不是**实验结论的来源（结论仍出自 `step4`/`step6`）。

### 13.9 一条依赖线，记住它就不会找错文件

```
models/ ─┐
data/  ──┼─→ face_system/ ←─ scripts/step0~6 ─→ outputs/step*/ ─┐
         │        ↑                                  ↑          ├─→ tools/ ─→ .docx / .html
         │        └──────── train/（只借 config 与 iresnet）      │
         └─→ data/lfw20_aligned/ ─→ train/ ─→ outputs/step7/ ────┘
                                        app/ ← face_system + outputs/gallery/
```

箭头只有一个方向：**被依赖的目录永远不 import 依赖它的目录**。
`face_system` 不知道 `scripts` 存在，`scripts` 不知道 `tools` 存在。所以任何一层都能单独替换或删除，这也是为什么这个工程在改动过程中没有出现过循环依赖。
